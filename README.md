# 터치라인 — 같은 선수, 하나의 기록

아마추어 축구 경기 영상을 올리면 선수를 찾아 따라가고, 선수별 복기 화면과 움직임 리포트를 만들어 주는 웹 서비스.
중앙대학교 소프트웨어학부 캡스톤디자인 6분반 5팀.

> 지금은 **뼈대 단계**다. 올리기 → 처리 → 복기 화면까지 이어지고, 기록 잇기와 경기장 맞추기는 서버 쪽만 동작한다(화면은 다음 단계).

## 흐름

1. **영상 올리기** — 고정 카메라 영상(mp4, mov). 영상 종류(파노라마 / 스마트폰)와 경기장 규격을 고른다.
2. **처리** — 영상 검사 → 재생용 준비 → 선수 검출 → 추적 → 결과 정리. 진행 상태가 목록에 보인다.
3. **복기 화면** — 선수를 누르면 확대 화면이 따라간다. 경기장을 맞추기 전에는 박스와 확대 화면만 나온다.
4. **기록 잇기** — 한 선수의 기록이 여러 조각으로 나뉘거나 다른 선수로 넘어간 곳을 사용자가 잇고 자른다.
5. **경기장 맞추기** — 화면에서 경기장 선의 교차점을 4개 이상 찍으면 미니맵과 리포트(거리, 속도, 고속 달리기, 활동 구역)가 열린다.
   점을 4개 찍을 수 없는 영상(카메라가 낮아 경기장이 잘린 영상)은 3번까지만 쓴다.

## 실행

```bash
pip install -r requirements.txt
uvicorn server.main:app --host 0.0.0.0 --port 8000
# 브라우저에서 http://localhost:8000
```

검출·추적에는 GPU와 가중치 파일이 필요하다. 가중치는 저장소에 넣지 않으며 `weights/`에 둔다.

| 환경 변수 | 뜻 | 기본값 |
|---|---|---|
| `TL_DATA` | 영상과 결과를 저장할 폴더 | `./data` |
| `TL_WEIGHTS_PANORAMA` | 파노라마 영상용 검출 가중치 | `weights/y11s_tile1280_e30_best.pt` |
| `TL_WEIGHTS_PHONE` | 스마트폰 영상용 검출 가중치 | `yolo11s.pt` (학습 전 기본 모델) |
| `TL_MAX_SEC` | 영상 길이 제한(초) | 600 |
| `TL_MAX_MB` | 파일 크기 제한(MB) | 2048 |
| `TL_DEV_TRACKS` | **개발용.** 검출·추적을 건너뛰고 이 추적 결과 파일을 쓴다 | 없음 |

GPU가 없는 PC에서 화면만 확인할 때:

```bash
TL_DEV_TRACKS=/경로/tracks_y11s_c2.txt uvicorn server.main:app --port 8000
```

## 검사

```bash
python -m pytest -q                                   # 계산 부분 (GPU 불필요)
tests/smoke_e2e.sh <영상.mp4> <추적결과.txt>          # 서버를 띄워 전체 흐름 한 번
```

## 구조

```
server/
  main.py            접수·상태·결과 API, 화면 파일 제공
  store.py           영상별 폴더에 파일로 저장 (DB 없음)
  pipeline/
    probe.py         영상 검사, 재생용 변환
    detect.py        선수 검출 (YOLO11, 원본 해상도)
    track.py         추적(BoT-SORT) + 끊긴 기록 잇기 + 짧은 빈 구간 채우기
    positions.py     화면 좌표 → 경기장 좌표
    metrics.py       거리, 속도, 고속 달리기, 스프린트, 활동 구역
    package.py       화면이 읽는 형식으로 묶기
    run.py           처리 순서와 진행 상태
web/                 화면 (빌드 과정 없는 HTML·CSS·JS)
tests/
docs/
```

API와 저장 형식은 [docs/API.md](docs/API.md), 정한 것과 남은 일은 [docs/결정과_남은일.md](docs/결정과_남은일.md)에 있다.
